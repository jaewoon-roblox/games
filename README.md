## 작업 재개 지점

독립 바이브 전환은 진행 중이며 아직 자동개발·런타임·게시 검증 완료가 아님.

- 웹 쪽 인계 기록: https://github.com/hans1177/jaewoon-games/pull/9413
- 로블 작업 브랜치: `work/independent-vibe`
- 이 브랜치에는 기존 바이브 import 의존성 85개와 로블 전용 정책·큐 경로 검증을 준비함.
- 중앙문서 정책 약 1.3MB에서 714KB로 1차 축소. 완전한 최소 정책 전환은 미완료.
- 집중 3개 Rojo 7.7.0 원시 빌드는 성공. 실제 게임 플레이·모바일·저장/재접속·게시 증거는 아직 없음.
- 정책 해석기 회귀 14개는 통과. 헌법 검사는 아직 미이전 모듈(외부 AI 증류·보안 학습·출처 원장 및 vibe-art-pipeline.js)을 요구하여 실패함.
- `.github/workflows/`의 기존 워크플로 3개는 검증용 스냅샷이며 필요한 도구·자산·조직 실행기·게시 키와 자체 상태 브랜치 이전 전까지 main에 활성화하면 안 됨.
- 원본의 큐·예약·성공 증거를 새 조직의 실행 성공으로 복제하지 말 것.
- 다음 작업: 위 누락 모듈과 자산/라이선스를 이전하고 헌법 검사 → 자체 빈 큐·런타임·학습 상태 초기화 → 독립 실행·게시 검증 → 실제 main 전환.

이 절은 진행 상태이며 중앙정책을 대체하지 않음. 상세 실패와 재개 순서는 웹 쪽 인계 기록을 함께 읽을 것.

## 2026-10-24 개발 대상 선별

- 기본 개발 대상은 기존 로블록스 46개 중 로블록스 네이티브 원본과 주요 클라이언트·서버·공용 설정 소스가 실제 존재하는 게임만 가능하다. 로블록스 파일 존재는 빌드·플레이·저장·게시 통과 증거가 아니다.
- 로블록스 조직 전용 기존 Vibe2 계획기가 중앙정책 `robloxDevelopmentInvestment.activePortfolio`를 사용한다. 우선 후보 심야 대탈출은 참조 중인 공용 모션 자산이 없어 빌드 준비 대상에서 대기한다. 실제 선정된 게임은 대충알피지 → 곤충 생존기 → 포근섬 → 마력숲 생존기 → 5포탈 RPG → 곤충 디펜스 6개다. 매 계획마다 실제 Rojo 프로젝트 파일 참조와 존재 여부를 재판정한다.
- 새 개발 작업 계획 목표는 집중 게임당 2개(총 12개)로 제한한다. 공유 작업자 자체 병렬 제한을 바꾸거나 실행 중인 작업을 취소하지 않는다. 후순위 후보는 삭제하지 않고 소스·소유자 우선순위를 매 계획마다 재평가한다.
- `ocean-voyage`는 현재 로블록스 저장소에 개발 소스가 없어 대상에서 제외하며, `cat-step`은 서버 소스가 없어 전체 클라이언트·서버 조건을 만족하지 못한다. 해당 게임의 정책 보류나 영구 폐기는 아니다.
- 자체 상태 브랜치 `vibe2-unreal-core`, `company-runtime`, `vibe2-learning-runtime`를 생성하고 빈 큐·기본 설정·로블록스 게임 카탈로그를 저장했다. 원래 통합 저장소의 실행 결과·이력·PASS 증거는 가져오지 않았다.
- 로블록스 조직 자체 Actions 실행 `40059012048`에서 헌법·정책·선별 회귀 검사 16개, 고정 해시 Rojo 7.7.0 기반 선정 6개 게임의 독립 패키지 빌드가 통과했다. 이는 빌드 준비 증거이며 바이브의 자동 코드 개발, 네이티브 플레이·모바일·저장/재접속·게시 성공은 아직 미검증이다.
- **미완료:** 기존 바이브의 아직 복사되지 않은 필수 실행 의존성, 자체 인증키/게시 키 연결, 정상 작업 스케줄링·F0~F9·런타임 검증. 기존 웹 저장소 자동화를 섣불리 끄거나 이 초안을 `main`에 병합하지 않는다.

## 2026-10-24 한방패치와 배포 후 검증

- **게임당 2개 / 전체 12개 제한 해제.** 우선순위 6개 선별은 유지하지만 한 게임에 임의의 작업 수 상한을 추가하지 않는다. 기존 큐·작업자 백프레셔, 책임 파일 충돌, 소유자 보류·보안 검사는 계속 적용한다.
- Roblox 조직 전용 `Vibe2 Continuous Core`의 기존 `workflow_dispatch`에서 `roblox_game`, `roblox_file`(생략 시 `*`), `roblox_goal`을 접수한다. `hans1177` 사용자가 해당 조직 저장소 `main`에서 직접 실행한 경우에만 작업이 기존 큐로 연결된다. 초안 브랜치에서 실행하지 않는다.
- 한방패치는 게임 내부 여러 Luau·UI·모션 설정의 책임 파일을 함께 선택할 수 있지만 다른 저장소, 다른 게임, 웹 소스, 바이너리 편집 우회를 허용하지 않는다. 기존 대기 중인 BUILD_UP과 병합하거나 현재 실행 중인 작업의 실제 파일 충돌만 기다린다.
- **배포 후 QA 순서:** 기존 F0 소스·패키지 최소 검증 → **별도 비공개 Roblox 후보 서버에 실제 배포** → 그 정확한 후보 버전에서 F1 서버 부팅·F2 월드·F3 캐릭터·F4 물리/이동·영향 받은 F5~F8 플레이/모바일/저장·F9 출시 회귀 → 완전히 검증된 동일 소스/아티팩트만 최종 서버에 배포. 기존 중앙정책의 F0~F9 순서를 변경하거나 생략하지 않는다.
- 변경 없는 동일 해시 증거만 재사용하며, 배포 실패나 미관측 플레이를 PASS로 기록하지 않는다. 검증에 실패하면 동일 기존 빌드업 작업을 수정·재검증한다.
- 작업 브랜치의 조직별 정적 검사·계획기·한방패치·배포 후 검증 순서 회귀는 Actions [40059914106](https://github.com/jaewoon-roblox/games/actions/runs/40059914106)에서 19/19 통과했고, 우선 6개 Rojo 원시 패키지 빌드도 통과했다.
- **실제 게임 배포/플레이·저장·모바일 검증은 아직 완료가 아니다.** 로블록스 조직의 별도 릴리스/비공개 배포 QA 워크플로와 인증키·실행기 연결, 필요한 기존 모듈 의존성 및 F0~F9 실제 실행이 남아 있다. 기존 정상 파이프라인 중단이나 이 초안 PR의 무검증 `main` 병합은 금지한다.
